## ✨ Features

- **Verified Nutrition Facts**: Serves reliable macronutrient and micronutrient data (calories, protein, fiber, vitamins, minerals) directly from a curated database.
- **Fact vs. AI Separation**: Nutrition facts are strictly database-sourced to prevent AI hallucinations. AI is utilized solely for explanations, meal ideas, and language translations.
- **Shared AI Knowledge Caching**: Responses generated by AI providers are cached in Cloudflare D1 to deliver instant, cost-free answers to subsequent visitors.
- **Multi-LLM Fallback**: Resilient AI provider manager (`Gemini` ➔ `Groq` ➔ `OpenRouter`).
- **Multilingual Support**: Real-time language switching between English (`en`), Telugu (`te`), and Hindi (`hi`).
- **Progressive Web App (PWA)**: Offline-first application shell caching via Service Worker (`sw.js`) and installable Web Manifest.
- **Privacy-Conscious**: No registration or login required. All user preferences (theme, language, saved items) are stored locally in `localStorage`.

## 🏛️ Architecture & Core Philosophy

```
User (Browser / PWA)
       │
       ▼
Static Frontend (HTML / CSS / JS Shell - Port 3000 / GitHub Pages)
       │
       ▼ (Fetch API with CORS)
Cloudflare Worker API (Port 8787 / Edge Serverless)
       │
       ├───► 1. Lookup verified nutrition from Cloudflare D1
       │
       ├───► 2. Check D1 Cache (`ai_content` / `ai_questions` tables)
       │        ├─── Hit  ──► Return cached AI response immediately
       │        └─── Miss ──► 3. Acquire Generation Lock
       │                           │
       │                           ▼
       │                      4. Multi-LLM Provider Manager (Gemini ➔ Groq ➔ OpenRouter)
       │                           │
       │                           ▼
       │                      5. Validate & Normalize Output
       │                           │
       │                           ▼
       │                      6. Save to D1 Database
       │                           │
       └───────────────────────────┴──► Return Normalized Output to User
```

## 🛠️ Tech Stack

| Layer | Technology | Description |
| :--- | :--- | :--- |
| **Frontend UI** | HTML5, Vanilla CSS3, ES6 JavaScript | Lightweight, fast SPA with dynamic theme management |
| **PWA & Caching** | Service Worker (`sw.js`), Web Manifest | Offline app shell caching & PWA installation |
| **Serverless API** | Cloudflare Workers (TypeScript) | Edge API proxy, request routing, CORS preflight handling |
| **Database** | Cloudflare D1 (Serverless SQLite) | Verified food catalog, nutrition tables, and AI response cache |
| **AI Providers** | Google Gemini API, Groq, OpenRouter | Multi-provider AI orchestration with automatic fallback |
| **Deployment** | GitHub Pages & Cloudflare Pages | Automated CI/CD deployment via GitHub Actions |

## 🚀 Getting Started & Local Development

### Prerequisites
- [Node.js](https://nodejs.org/) (v18 or higher)
- `npm` (v9 or higher)

---

### 1. Running Frontend Locally

From the root directory (`healthfood-ai`):

```powershell
# Serve static files locally
npx serve .
```

* The frontend application will open on `http://localhost:3000`.
* Alternatively, open `index.html` directly in any modern browser.

---

### 2. Running Backend API Worker Locally

In a new terminal window, navigate into the `worker` directory and start Wrangler dev server:

```powershell
cd worker

# Install dependencies if running for the first time
npm install

# Start Cloudflare Worker dev server
npm run dev
```

* The backend API server will start on `http://localhost:8787` (or `http://127.0.0.1:8787`).
* It automatically binds to your local Cloudflare D1 SQLite database environment.

## 🌐 API Endpoints

| Method | Endpoint | Description |
| :--- | :--- | :--- |
| `GET` | `/api/health` | Health check endpoint returning API status & timestamp |
| `GET` | `/api/config` | App configurations, disclaimers, and supported languages |
| `GET` | `/api/categories` | Retrieve all food categories |
| `GET` | `/api/foods` | Fetch food items (supports `?category=...` and `?search=...`) |
| `GET` | `/api/foods/:slug` | Fetch detailed nutrition profile for a single food item |
| `GET` | `/api/daily-tip` | Fetch daily nutrition tip in target language (`?lang=en|te|hi`) |
| `POST` | `/api/ai/question` | Ask AI assistant custom nutrition questions with D1 caching |

## 🗄️ Database Schema (Cloudflare D1)

The backend utilizes Cloudflare D1 (serverless SQLite). Key tables include:

- `foods`: Basic food information (`id`, `slug`, `name`, `scientific_name`, `category_id`, `vegetarian`, `image_url`)
- `nutrition`: Detailed macronutrients & micronutrients (`calories`, `protein_g`, `carbs_g`, `fat_g`, `fiber_g`, `vitamins`, `minerals`)
- `categories`: Category names, icons, and slugs
- `ai_content`: Cached AI-generated explanations and translations
- `ai_questions`: Cached custom Q&A hash lookup
- `generation_locks`: Prevents thundering herd duplicate AI calls

```powershell
npm run deploy
```
